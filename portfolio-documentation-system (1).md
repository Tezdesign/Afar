# Portfolio Documentation System

A two-layer system so you document once and apply fast, without re-deriving your story every time.

---

## LAYER 1 — Living Project Record
*One of these per project — any product, freelance job, or personal build, past or current. Update it as you build — weekly, not retroactively. This is for you.*

### 1. Snapshot
- One-line description
- Type (personal project / freelance / employment / academic)
- Status (active / paused / shipped)
- Your role(s)
- Stack / tools

### 2. Problem & Context
- What real problem does this solve, for whom
- Constraints you were working under (solo build, timeline, tech limits)

### 3. Key Decisions Log
*The most valuable section — append to this every time you make a nontrivial call.*
| Date | Decision | Why | Alternative considered | Result |
|---|---|---|---|---|

### 4. System & Craft
- Design system contributions (tokens, components — link to your shared system if one applies)
- Notable interaction/behavioral design choices (name the mechanism, not just the screen — e.g. loss aversion, progressive disclosure, social proof)
- Edge cases you stress-tested and how

### 5. Evidence
- Screens / Figma links (node-id links, not full file)
- Before → after if reworked
- Metrics if you have them (even rough ones: "cut onboarding taps from 9 to 4")

### 6. Reflection
- What you'd change if starting over
- What this taught you that transfers to other projects

## LAYER 2 — Case Study (extraction template)
*Never write from scratch. Pull from Layer 1. Aim for 30 minutes per application. Tailor to the role.*

### Title
[Project name] — [the specific angle for this application]
*e.g. same project, two angles: "Designing a Design System That Survives Multiple Products" vs "Behavioral Design in a Habit-Forming App" — pick the angle that matches what the role cares about.*

### Structure (fits one page or 4–6 slides)
1. **Problem** (2–3 sentences, pulled from Section 2)
2. **Your role & constraints** (1–2 sentences)
3. **The key decision(s)** — pick 1–2 from your Decisions Log that best match what this role cares about
4. **Show, don't narrate** — 2–4 screens/flows max, annotated
5. **Outcome / what changed**
6. **What you'd do differently** (shows judgment, not just execution)

### Role-fit filter (pick before writing)
List the 2–3 role types you typically apply for, and what each one should lead with. Examples:
- [ ] Design-focused role → lead with Decisions Log + behavioral/UX rationale
- [ ] Dev-focused role → lead with architecture, technical pipeline, edge cases handled
- [ ] Hybrid/end-to-end role → lead with your system (design system, shared architecture) as the throughline across projects

## Cadence
- **Weekly (15 min):** update Decisions Log for whatever you touched
- **Monthly (30 min):** review Story Bank, add new tagged fragments
- **Per opportunity:** extract Layer 2 case study from existing Layer 1 — never author from zero
